Start here

Create your GitHub repository

GitHub is the central home for your project. It stores your code, tracks changes, supports collaboration, and gives GitHub Actions a place to run.

Open GitHub's new repository page ↗
✓
Checkpoint

Your new repository contains README.md and .gitignore.

02

Bring it local

Clone the repository to VS Code

Cloning creates a local working copy. You will edit files on your computer, then use Git to send those changes back to GitHub.

Terminal 
git status
What to look for

A clean working tree means Git sees no uncommitted changes yet. That is a useful baseline before you start building.

03

Isolate your work

Set up a Python virtual environment

.venv creates a private Python environment for this project. Packages installed here will not interfere with other projects on your computer.

✓
Checkpoint

Your terminal prompt should begin with (.venv). The .venv folder is local only and should never be committed.

04

Declare the recipe

Create requirements.txt

A requirements file records the packages the project needs. Anyone, including GitHub Actions, can install the same dependencies from this one small list.

The connection

When GitHub Actions runs later, it will read this same file and install pytest in its fresh environment.

05

Standardize the routine

Create a Makefile

A Makefile gives the team memorable shortcuts for common commands. Instead of remembering several commands, you can use simple commands such as make test.

Important

Makefile commands must begin with a real TAB character, not spaces. If you copy the Makefile above, the indentation is already included.

06

Package the environment

Run the project with Docker

Docker packages your project and its dependencies into a portable image. Anyone with Docker can build the same image and run the same application without installing Python locally.

Why use Docker?

A virtual environment isolates packages on your computer. Docker goes one step further by describing the Python version, dependencies, files, and startup command together. This makes the project easier to reproduce on another laptop or in a CI/CD environment.

Expected result

Docker builds successfully, the program runs in the container, and the test suite passes there too.

07

Automate the check

Add GitHub Actions

GitHub Actions runs repeatable tasks in the cloud when code changes. You will create a workflow that automatically installs your dependencies and runs your tests.

name Label for the workflow.
on Events that start it.
jobs Work to perform.
runs-on Machine to use.
steps Ordered actions and commands.

09

Your homework

Document your work in a README

A README is the project guide for anyone who visits your repository. It explains what the project does, how to run it, and what to look at first.

Expected result

Your README should clearly explain the project and make it easy for someone else to understand and run your code.

10

Push the project to GitHub. Actions will create a fresh environment, check out your files, install Python and pytest, and run your test suite.
